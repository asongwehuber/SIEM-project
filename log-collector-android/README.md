# Android SIEM Collector

An Android-based security telemetry collector designed to monitor security-relevant events on Android devices and securely forward them to a centralized SIEM infrastructure.

The collector is part of a broader multi-source SIEM project and acts as the Android endpoint component.

---

## Overview

The Android SIEM Collector runs on an Android device and collects security-related events generated by the device.

Collected events are structured into a standardized format, authenticated using HMAC-SHA256, and transmitted to the SIEM Agent for verification, normalization, detection, and further processing.

The collector is designed to operate alongside the Android device without requiring continuous interaction with the application interface.

## Features

### Security Event Collection

The collector supports the generation and transmission of several Android security events, including:

* Failed login events
* Port scan events
* Suspicious application activity
* Application installation
* Application uninstallation
* Application security findings

### Application Security Monitoring

The collector analyzes installed user applications and evaluates their security profiles.

It can detect:

* Newly installed applications
* Removed applications
* Changes to an application's security profile
* Sensitive permissions requested by applications
* Sensitive permissions currently granted to applications
* Changes in granted sensitive permissions

### Sensitive Permission Analysis

The collector currently evaluates sensitive permissions including:

* Camera
* Microphone
* Fine location
* Coarse location
* Contacts
* Call logs
* SMS
* Phone state
* Phone calls
* External storage
* Bluetooth

Application findings are assigned a severity based on the number of sensitive permissions granted:

| Granted Sensitive Permissions | Severity |
| ----------------------------: | -------- |
|                             1 | LOW      |
|                           2–3 | MEDIUM   |
|                     4 or more | HIGH     |

System applications are excluded from the application-security analysis.

---

## Background Monitoring

Application-security analysis can be scheduled using Android WorkManager.

The collector uses periodic background execution to analyze application security profiles without requiring the user to keep the SIEM application interface open.

The current periodic monitoring interval is **15 minutes**.

Android may adjust the exact execution time depending on system conditions, battery optimization, and background execution policies.

## Security

Security is an important part of the collector-to-SIEM communication process.

### HMAC-SHA256

Each event is authenticated using HMAC-SHA256 before transmission.

The signature is generated using the shared SIEM secret and event data.

This allows the SIEM Agent to verify that the event originated from a trusted collector and has not been modified during transmission.

### Timestamp Validation

Events contain timestamps generated using the configured SIEM timestamp format.

The SIEM Agent validates the timestamp and rejects events outside the permitted time window.

### Replay Protection

Each event contains a unique event ID.

The SIEM Agent maintains replay protection to prevent previously accepted events from being submitted again.

## Event Format

The collector sends events to the SIEM Agent using JSON.

A simplified event has the following structure:

```json
{
  "timestamp": "19/09/2026 04:58:30",
  "event_id": "ANDROID-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "generator_id": "android-phone-01",
  "hostname": "Samsung-SM-F926B",
  "message": "...",
  "signature": "..."
}
```

Application-security information is carried inside the `message` field.

Example:

```json
{
  "event_type": "application_security",
  "event_category": "android_application",
  "severity": "high",
  "application_name": "Snapchat",
  "package_name": "com.snapchat.android",
  "application_type": "USER",
  "requested_sensitive_permissions": [],
  "granted_sensitive_permissions": [],
  "is_new_application": false,
  "permissions_changed": true,
  "reason": "User application security profile changed"
}
```

## Configuration

The collector stores its SIEM configuration using Android DataStore.

The main configuration values are:

```text
SIEM Agent IP Address
SIEM Agent Port
Collector ID
```

Example:

```text
IP Address: 192.168.1.171
Port: 6000
Collector ID: android-phone-01
```

The SIEM secret key is supplied through the local Gradle configuration.

**Do not commit the secret key or `local.properties` to Git.**

## Running the Collector

### Requirements

* Android Studio
* Android SDK
* Android device or Android emulator
* SIEM Agent running and reachable from the Android device
* Correct SIEM secret configuration

### Steps

1. Clone the repository.

2. Open the project in Android Studio.

3. Configure the local SIEM secret in `local.properties`.

4. Verify the SIEM Agent IP address and port in the application.

5. Connect an Android device or start an emulator.

6. Build and run the application.

7. Save the SIEM configuration.

8. Test the connection to the SIEM Agent.

## SIEM Communication

The Android collector communicates with the SIEM Agent through:

```text
POST /receive-log
```

The SIEM Agent listens on port:

```text
6000
```

The Android collector does not communicate directly with the SIEM database.

The communication path is:

```text
Android Collector
        ↓
SIEM Agent
        ↓
SIEM Application Server
        ↓
Database
```

This ensures that logs pass through the SIEM Agent's security validation and normalization process before reaching the SIEM platform.

## Privacy and Security Considerations


The project includes an example `local.properties` file to show the configuration required by the Android SIEM Collector.

Before building the application, create or update `local.properties` in the root directory of the project with your local Android SDK path and SIEM configuration.

Example:

```properties
sdk.dir=C\:\\Users\\YOUR_USERNAME\\AppData\\Local\\Android\\Sdk

SIEM_SECRET_KEY=YOUR_SIEM_SECRET_KEY
```

Replace:

* `YOUR_USERNAME` with the username on your development machine.
* `YOUR_SIEM_SECRET_KEY` with the same secret key configured for the SIEM Agent.

The `SIEM_SECRET_KEY` must match the secret configured on the SIEM Agent so that HMAC-SHA256 signatures can be verified successfully.

### Example Configuration File

The repository contains a safe example configuration file:

```text
local.properties.example
```

Copy it to:

```text
local.properties
```

Then edit the values according to your local environment.

For example:

```text
local.properties.example
        ↓
   copy/rename
        ↓
local.properties
        ↓
fill in local values
        ↓
Build the Android application
```

The example file must contain **placeholder values only** and must never contain a real SIEM secret.

> **Important:** `local.properties` is used for local configuration and should remain excluded from Git. Only `local.properties.example` should be committed to the repository.
